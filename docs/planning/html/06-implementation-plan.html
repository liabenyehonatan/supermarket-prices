02 Stage 9 in detail: the map view

  1. Two quick checks. How many stores really have a position (about 86% did), and a trial cut of the Israel map to see its size and whether Hebrew labels look right.
  2. Choose the map source. Recommended: host the map file on our own server, so there are no usage limits, no outside dependency and no change to the privacy text.
  3. Pins with totals, cheapest highlighted, clusters when zoomed out, stores missing items in grey.
  4. List and map together: moving the map updates the list; a pin opens the store with navigation. The map loads only when asked for.
  5. Test on phones with 100 stores, with and without location permission.

03 What could go wrong

RiskWhat we do
A chain changes its site and the download fails (often)That chain fails alone; the library is pinned and upgraded on purpose; an alert fires after 5 silent days.
Promotion files make runs long or fill the diskA run takes 2 to 3 hours and the disk has room; promotions can be limited to some chains or switched off with one setting.
Wrong prices or stale promotions in chain filesFake prices are filtered; promotions count only when fresh and clearly safe; deals must beat the shelf price.
One server is a single point of failureAccepted for now: nightly backups copied off the server, and recovery = restore + re-run the Worker.
Missing or approximate store positions (for the map)An accuracy flag, and stores without a position are listed under the map.
