# פרומפט ל-Claude Web: Google Search Console ואנליטיקס

העתיקו את הטקסט שבתוך הבלוק לשיחה חדשה ב-Claude (claude.ai). החליפו את `<DOMAIN>` בדומיין האמיתי.

```
אני מפעילה אתר השוואת מחירי סופרמרקט בעברית (RTL) בשם "סלי". הכתובת: https://<DOMAIN>
תנחה אותי צעד אחר צעד, בעברית, להגדיר את Google Search Console ומדידת תנועה. שאל אותי שאלה אחת בכל פעם
ואל תניח שעשיתי משהו לפני שאישרתי.

מה שכבר קיים באתר (בצד הקוד):
- robots.txt ב-https://<DOMAIN>/robots.txt, שמפנה ל-sitemap.
- sitemap index ב-https://<DOMAIN>/sitemap.xml, שמפנה ל-/sitemap-pages.xml ול-/sitemap-products-1.xml, -2.xml ... (עד 40,000 כתובות בכל קובץ, כ-200 אלף עמודי מוצר).
- בכל עמוד: title, description, canonical, Open Graph ו-JSON-LD (WebSite, Product עם AggregateOffer, BreadcrumbList).
- עמוד שלא קיים מחזיר 404 אמיתי.
- האתר מוגש מאחורי Caddy (HTTPS) ו-nginx. אין לי גישה לשינוי ה-HTML ישירות, רק לקובץ .env ולשרת.

חלק 1, Google Search Console:
1. הוסף נכס מסוג "Domain" (לא "URL prefix"). תן לי את רשומת ה-TXT ל-DNS ולמד אותי איפה מכניסים אותה אצל הרשם שלי (אשאל אותך מי הרשם).
2. אחרי האימות: שלח את https://<DOMAIN>/sitemap.xml דרך תפריט "Sitemaps". הסבר מה לצפות לראות (סטטוס Success, ומספר כתובות שהתגלו בכל קובץ משנה) וכמה זמן לוקח.
3. הסבר איך להשתמש ב"URL Inspection" על 3 כתובות: דף הבית, /promotions ועמוד מוצר אחד (למשל /product/<ברקוד>), ומה לבדוק: "Page is indexable", ה-canonical שגוגל בחר, ו-"View crawled page" כדי לוודא שהוא רואה כותרת ותוכן בלי הרצת JavaScript.
4. בדיקת Rich Results (https://search.google.com/test/rich-results) על עמוד מוצר: מה אמור להופיע (Product, Breadcrumb), ומה לעשות אם יש אזהרות.
5. הסבר איך לקרוא את הדוחות בשבועות הראשונים: Pages (Indexed / Not indexed וסיבות נפוצות כמו "Discovered – currently not indexed" או "Crawled – currently not indexed"), Performance (שאילתות, קליקים, מיקום), Core Web Vitals, ו-Enhancements (Breadcrumbs, Products).
6. הוסף גם Bing Webmaster Tools (ייבוא מ-Search Console) בקצרה.
7. תן לי רשימת בדיקה שבועית של 10 דקות, ומה אמורה להיות התוצאה אחרי חודש, שלושה חודשים ושישה חודשים (ריאלית, עבור אתר חדש עם הרבה עמודים דומים).

חלק 2, אנליטיקס. יש אילוץ חשוב:
- עמוד "אודות" באתר מבטיח למשתמשים: "אין הרשמה, אין עוגיות ואין מעקב או ניתוח התנהגות". אני לא רוצה לשבור את ההבטחה הזאת בלי להחליט על כך במודע.
- ה-Content-Security-Policy ב-nginx מרשה סקריפטים רק מ-'self' ו-connect-src רק ל-'self', כלומר כל כלי אנליטיקס חיצוני ייחסם עד שאשנה את ה-CSP.
תציג לי בקצרה את האפשרויות עם יתרונות וחסרונות, ותמליץ על אחת:
  א. Plausible או Umami (אפשר Self-hosted ב-docker compose הקיים): בלי עוגיות, בלי מידע אישי, אין צורך בבאנר הסכמה, ואפשר להגיש את הסקריפט מהדומיין שלי כך שה-CSP כמעט לא משתנה.
  ב. Google Analytics 4: חינמי ועשיר, אבל עוגיות ומעקב, ולכן צריך באנר הסכמה ועדכון של עמוד אודות ושל מדיניות הפרטיות.
  ג. רק Search Console בלי אנליטיקס נוסף (הפתרון הפשוט ביותר ששומר על ההבטחה).
אחרי שאבחר, תן לי:
- את ההוראות המדויקות להתקנה (איפה מוסיפים את השורה: בקובץ frontend/index.html, בסמוך ל-<head>; מה לשנות ב-nginx/nginx.conf ב-script-src וב-connect-src, ושורה אחת בלבד בכל שינוי).
- נוסח מעודכן לעמוד "אודות" בסעיף הפרטיות, בעברית, שמתאר במדויק מה נמדד.
- אילו אירועים כדאי למדוד: חיפוש מוצר, פתיחת עמוד מוצר, הוספה לסל, השוואת סל, לחיצה על מבצע, סריקת ברקוד. בלי שום מידע מזהה.
- איך לחבר את Search Console לאנליטיקס (ב-GA4) או לעקוב אחר מקורות תנועה (ב-Plausible/Umami).
- דוח בסיסי שכדאי לבדוק כל שבוע: העמודים עם הכי הרבה כניסות מגוגל, שאילתות שמביאות תנועה, ושיעור נטישה בעמוד מוצר.

אל תכתוב קוד לאתר עצמו מעבר לשורות ההטמעה. את השינויים בקוד אבצע בעזרת Claude Code.
```

## מה חשוב לדעת לפני

- **הדומיין חייב להיות מוגדר ב-`.env`** (`SITE_URL=https://<DOMAIN>`), אחרת הכתובות ב-canonical וב-sitemap ייבנו לפי הכתובת שהבקשה הגיעה אליה (למשל כתובת ה-IP).
- **Search Console לא משנה את מה שהאתר מבטיח למשתמשים** (הוא לא מודד אותם). אנליטיקס כן, ולכן הפרומפט מציג את האפשרויות ולא מכריע.
